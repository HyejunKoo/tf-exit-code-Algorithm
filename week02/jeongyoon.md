# 오답노트

## 문제 1

### 문제 정보

- 문제명: 올바른 괄호
- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12909
- 사용한 알고리즘 / 자료구조: Stack

### 처음 접근 방식

문제를 읽고 가장 먼저 괄호의 짝을 확인해야 한다고 생각했다. 여는 괄호가 나오면 저장해 두고, 닫는 괄호가 나오면 가장 최근에 나온 여는 괄호와 짝이 맞는지 확인하면 될 것 같아서 `Stack`을 사용하기로 했다.

### 풀이 방법

문자열을 앞에서부터 하나씩 확인하면서 괄호를 처리하였다.

1. `'('`가 나오면 `Stack`에 넣는다.
2. `')'`가 나오면 `Stack`이 비어 있는지 먼저 확인한다.
3. 비어 있다면 짝이 맞지 않는 것이므로 바로 `false`를 반환한다.
4. 비어 있지 않다면 `Stack`에서 하나를 꺼내 짝을 맞춘다.
5. 문자열을 모두 확인한 뒤 `Stack`이 비어 있으면 모든 괄호의 짝이 맞은 것이므로 `true`를 반환하고, 남아 있다면 `false`를 반환한다.

```java
import java.util.*;

class Solution {
    boolean solution(String s) {

        Stack<Character> stack = new Stack<>();

        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);

            if (c == '(') {
                stack.push(c);
            } else {
                if (stack.isEmpty()) {
                    return false;
                }
                stack.pop();
            }
        }

        return stack.isEmpty();
    }
}
```

### 어려웠던 지점

처음에는 문자열을 끝까지 확인한 뒤 여는 괄호와 닫는 괄호의 개수만 같으면 되는 것이 아닐까 생각했다. 하지만 `")()("`처럼 개수는 같아도 순서가 잘못된 경우가 있기 때문에 이 방법으로는 해결할 수 없었다.

또한 닫는 괄호가 먼저 나오는 경우에는 `Stack`이 비어 있는데 `pop()`을 호출하면 오류가 발생할 수 있다는 점도 신경 써야 했다.

### 해결 방법

닫는 괄호를 만날 때마다 `Stack`이 비어 있는지 먼저 확인하도록 수정했다.

비어 있다면 더 이상 확인할 필요 없이 바로 `false`를 반환하도록 하였고, 모든 문자를 확인한 뒤에도 `Stack`에 여는 괄호가 남아 있다면 짝이 맞지 않은 것이므로 `false`를 반환하였다.

### 시간복잡도 / 공간복잡도

- **시간복잡도:** **O(N)**
    - 문자열을 한 번만 순회하면서 괄호를 확인한다.
- **공간복잡도:** **O(N)**
    - 최악의 경우 모든 문자가 `'('`인 경우 `Stack`에 모두 저장될 수 있다.

### 새롭게 알게 된 점

이번 문제를 풀면서 괄호처럼 가장 최근에 들어온 데이터를 먼저 확인해야 하는 문제에서는 `Stack`이 잘 어울린다는 것을 다시 느꼈다.

또한 단순히 개수를 세는 것만으로는 해결되지 않고, 괄호가 나온 순서까지 함께 확인해야 한다는 점이 중요했다.

앞으로도 괄호 검사나 짝을 맞추는 문제가 나오면 `Stack`을 먼저 떠올려 보면 좋을 것 같다.

## 문제 2

### 문제 정보

- 문제명: 프로세스
- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42587
- 사용한 알고리즘 / 자료구조: PriorityQueue, 구현

### 처음 접근 방식

처음에는 문제 설명대로 `Queue`를 이용해서 프로세스를 하나씩 꺼내고 다시 넣는 방식으로 구현하려고 했다. 하지만 우선순위가 가장 높은 프로세스를 계속 확인해야 해서 조금 번거롭다고 생각했다.

그래서 가장 높은 우선순위만 빠르게 알 수 있으면 된다고 판단했고, `PriorityQueue`를 이용해 현재 남아 있는 프로세스 중 가장 높은 우선순위를 관리하는 방식으로 구현하였다.

### 풀이 방법

우선 모든 우선순위를 내림차순 `PriorityQueue`에 넣었다.

그 후 반복문을 돌면서 현재 가장 높은 우선순위(`pq.peek()`)와 `priorities` 배열의 값을 비교하였다.

1. 현재 가장 높은 우선순위와 같은 프로세스를 찾는다.
2. 실행된 것으로 처리하기 위해 `PriorityQueue`에서 제거하고 실행 횟수를 증가시킨다.
3. 실행한 프로세스의 인덱스가 `location`과 같다면 현재 실행 순서를 반환한다.
4. `PriorityQueue`가 빌 때까지 같은 과정을 반복한다.

```java
import java.util.*;

class Solution {
    public int solution(int[] priorities, int location) {

        int answer = 0;
        PriorityQueue<Integer> pq = new PriorityQueue<>(Collections.reverseOrder());

        for (int priority : priorities) {
            pq.offer(priority);
        }

        while (!pq.isEmpty()) {
            for (int i = 0; i < priorities.length; i++) {
                if (priorities[i] == pq.peek()) {
                    pq.poll();
                    answer++;

                    if (i == location) {
                        return answer;
                    }
                }
            }
        }

        return answer;
    }
}
```

### 어려웠던 지점

처음에는 문제 설명만 보고 `Queue`를 직접 구현해야 하는 줄 알았다.

하지만 실제로 필요한 것은 현재 남아 있는 프로세스 중 가장 높은 우선순위를 계속 확인하는 것이었기 때문에, 이를 어떻게 효율적으로 구현할지 고민했다.

또한 같은 우선순위를 가진 프로세스가 여러 개 있을 수 있기 때문에 실행 순서가 원래 배열의 순서를 유지하도록 처리하는 부분도 신경 써야 했다.

### 해결 방법

가장 높은 우선순위는 `PriorityQueue`에서 관리하고, 실제 실행 순서는 원래 `priorities` 배열을 앞에서부터 확인하는 방식으로 해결했다.

이렇게 구현하니 별도의 `Queue`를 직접 관리하지 않아도 문제에서 요구하는 실행 순서를 그대로 구현할 수 있었다.

### 시간복잡도 / 공간복잡도

- **시간복잡도:** **O(N²)**
    - 최악의 경우 `PriorityQueue`의 모든 원소를 꺼낼 때마다 배열 전체를 한 번씩 확인한다.
- **공간복잡도:** **O(N)**
    - 우선순위를 저장하기 위해 `PriorityQueue`를 사용하였다.

### 새롭게 알게 된 점

이번 문제를 풀면서 문제에서 특정 자료구조를 사용하는 것처럼 보여도 꼭 그대로 구현할 필요는 없다는 것을 배웠다.

핵심은 현재 가장 높은 우선순위를 빠르게 찾는 것이었고, 이 부분을 `PriorityQueue`로 해결하니 코드도 훨씬 간단해졌다.

다음에 비슷한 문제가 나온다면 문제의 동작을 그대로 구현하기보다 필요한 기능이 무엇인지 먼저 생각해 보고 적절한 자료구조를 선택해야겠다고 느꼈다.

## 문제 3

### 문제 정보

- 문제명: 다리를 지나는 트럭
- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42583
- 사용한 알고리즘 / 자료구조: Queue, 시뮬레이션

### 처음 접근 방식

처음에는 다리 위에 있는 트럭들을 직접 이동시키면서 구현하려고 했다. 하지만 트럭마다 이동 거리를 따로 관리하면 구현이 복잡해질 것 같았다.

그래서 다리 자체를 하나의 `Queue`로 생각했다. 큐의 길이를 다리의 길이와 같게 유지하면 시간이 1초씩 흐를 때마다 트럭이 한 칸씩 이동하는 것과 같은 효과를 낼 수 있다고 생각했다.

### 풀이 방법

다리 위의 상태를 `Queue`로 관리하였다.

1. 다리 위에 아무 트럭도 없으면 바로 트럭을 올린다.
2. 다리 길이만큼 트럭이 올라가 있다면 맨 앞의 트럭을 꺼내 다리를 빠져나가도록 한다.
3. 다음 트럭을 올려도 무게 제한을 넘지 않으면 다리에 올린다.
4. 무게 제한을 넘는다면 `0`을 큐에 넣어 한 칸 이동한 것처럼 처리한다.
5. 모든 트럭을 다리에 올린 뒤에는 마지막 트럭이 다리를 완전히 건너는 시간(`bridge_length`)을 더해 결과를 반환하였다.

```java
import java.util.*;

class Solution {
    public int solution(int bridge_length, int weight, int[] truck_weights) {

        Queue<Integer> queue = new LinkedList<>();

        int sum = 0;
        int time = 0;

        for (int truck : truck_weights) {

            while (true) {

                if (queue.isEmpty()) {
                    queue.offer(truck);
                    sum += truck;
                    time++;
                    break;
                }

                if (queue.size() == bridge_length) {
                    sum -= queue.poll();
                } else {
                    if (sum + truck <= weight) {
                        queue.offer(truck);
                        sum += truck;
                        time++;
                        break;
                    } else {
                        queue.offer(0);
                        time++;
                    }
                }
            }
        }

        return time + bridge_length;
    }
}
```

### 어려웠던 지점

가장 어려웠던 부분은 트럭이 다리에 올라가지 못하는 시간을 어떻게 표현할지였다.

처음에는 트럭이 올라갈 수 있을 때까지 기다리는 방식으로 생각했는데, 시간이 흐르는 것을 코드로 표현하기가 쉽지 않았다.

또한 다리 위의 트럭이 한 칸씩 이동하는 과정을 따로 구현하려고 하니 코드가 복잡해졌다.

### 해결 방법

다리의 빈 공간을 `0`으로 표현하는 방법을 사용했다.

무게 제한 때문에 트럭을 올릴 수 없는 경우에는 `0`을 큐에 넣어 시간을 1초 증가시키고, 기존 트럭들이 앞으로 한 칸 이동하도록 만들었다.

이렇게 구현하니 트럭의 위치를 따로 관리하지 않아도 자연스럽게 시간이 흐르는 상황을 표현할 수 있었다.

### 시간복잡도 / 공간복잡도

- **시간복잡도:** **O(N + L)**
    - 각 트럭은 한 번 다리에 올라가고 한 번 빠져나오며, 큐에서의 연산은 모두 O(1)이다.
    - (`N`: 트럭의 수, `L`: 다리 길이)
- **공간복잡도:** **O(L)**
    - 다리 위의 상태를 저장하기 위해 최대 `bridge_length` 크기의 `Queue`를 사용하였다.

### 새롭게 알게 된 점

이번 문제를 풀면서 시뮬레이션 문제는 실제 상황을 그대로 구현하려고 하기보다, 적절한 자료구조로 단순하게 표현하는 것이 더 중요하다는 것을 느꼈다.

특히 `0`을 이용해 빈 공간을 표현하는 방법이 인상적이었다. 덕분에 트럭의 위치를 따로 계산하지 않아도 시간의 흐름과 이동을 자연스럽게 구현할 수 있었다.

앞으로 비슷한 시뮬레이션 문제를 만나면 모든 상태를 직접 계산하기보다 자료구조를 활용해 간단하게 표현할 수 있는 방법을 먼저 생각해 봐야겠다.
