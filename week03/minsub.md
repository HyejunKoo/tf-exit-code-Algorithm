# 문제 1

## 문제 정보

* **문제명:** 33. Search in Rotated Sorted Array
* **문제 링크:** https://leetcode.com/problems/search-in-rotated-sorted-array/description/
* **사용한 알고리즘 / 자료구조:** 이분 탐색(Binary Search)

---

## 처음 접근 방식

처음에는 일반적인 이분 탐색을 그대로 적용하려고 했다.

배열의 중간값(`mid`)과 `target`을 비교하여,

* `nums[mid] > target`이면 왼쪽 범위를 탐색하고,
* `nums[mid] < target`이면 오른쪽 범위를 탐색하는 방식으로 접근하였다.

하지만 문제의 배열은 **회전된 정렬 배열(Rotated Sorted Array)** 이기 때문에 단순히 `mid`와 `target`만 비교해서는 탐색 방향을 결정할 수 없었다.

예를 들어,

```text
[4, 5, 6, 7, 0, 1, 2]
```

에서 `target = 0`인 경우,

* `mid = 7`
* `7 > 0`

이지만 실제 정답은 오른쪽에 존재한다.

즉, 일반 이분 탐색의 전제가 되는 **"배열 전체가 정렬되어 있다."** 는 조건이 성립하지 않는다는 점을 처음에는 제대로 고려하지 못했다.

---

## 풀이 방법

이 문제의 핵심은 **회전된 배열이라도 항상 한쪽 구간은 정렬되어 있다**는 성질을 이용하는 것이다.

### 1. mid가 target인지 확인한다.

```java
if (nums[mid] == target)
```

정답이라면 즉시 해당 인덱스를 반환한다.

### 2. 왼쪽 구간이 정렬되어 있는지 확인한다.

```java
nums[left] <= nums[mid]
```

이 조건이 참이면

```
[left ~ mid]
```

구간이 오름차순으로 정렬되어 있다는 의미이다.

### 3. target이 정렬된 왼쪽 구간 안에 존재하는지 확인한다.

```
nums[left] <= target < nums[mid]
```

* 포함된다면 오른쪽 구간을 버리고

  ```
  right = mid - 1
  ```
* 포함되지 않는다면 왼쪽 구간을 버리고

  ```
  left = mid + 1
  ```

### 4. 오른쪽 구간이 정렬되어 있는 경우

왼쪽이 정렬되어 있지 않다면 오른쪽 구간이 정렬되어 있다.

```
[mid ~ right]
```

이 구간 안에 target이 존재하는지 확인한 후,

* 포함되면

  ```
  left = mid + 1
  ```
* 포함되지 않으면

  ```
  right = mid - 1
  ```

를 수행한다.

이 과정을 반복하면 탐색 범위를 절반씩 줄이며 O(log N) 안에 target을 찾을 수 있다.

---

## 어려웠던 지점

가장 어려웠던 부분은 **일반 이분 탐색을 그대로 적용하려고 했던 점**이었다.

처음에는

```java
if(nums[mid] > target)
```

이면 왼쪽,

```java
else
```

이면 오른쪽으로 이동하는 방식으로 구현했는데,

회전된 배열에서는 이러한 비교만으로는 target의 위치를 판단할 수 없었다.

또한 이분 탐색 문제를 풀면서 항상 어려웠던 부분은

* 어떤 기준으로 탐색 범위를 줄여야 하는지
* 마지막에 무엇을 반환해야 하는지

를 정확하게 판단하는 것이었다.

---

## 해결 방법

회전된 배열에서는 **mid와 target만 비교하는 것이 아니라, 먼저 어느 구간이 정렬되어 있는지를 확인해야 한다**는 점을 이해하면서 해결할 수 있었다.

과정은 다음과 같다.

1. 왼쪽이 정렬되어 있는가?
2. 아니라면 오른쪽이 정렬되어 있는가?
3. target이 정렬된 구간 안에 존재하는가?
4. 존재하면 그 구간만 남기고, 아니라면 반대 구간만 남긴다.

즉,

> **정렬된 구간을 먼저 찾고, target이 그 구간 안에 있는지 판단하여 탐색 범위를 절반으로 줄이는 것**이 문제의 핵심이었다.

---

## 시간복잡도 / 공간복잡도

* **시간복잡도:** O(log N)
* **공간복잡도:** O(1)

---

## 새롭게 알게 된 점

이번 문제를 통해 **회전된 정렬 배열에서의 이분 탐색은 일반 이분 탐색과 탐색 기준 자체가 다르다**는 것을 배웠다.

이후 비슷한 문제를 만나면 다음 순서대로 접근할 예정이다.

1. 이분 탐색 적용이 가능한 문제인지 확인한다.
2. 탐색 범위를 절반으로 줄일 수 있는 기준이 무엇인지 찾는다.
3. 일반 정렬 배열인지, 회전 배열인지 등 추가 조건을 확인한다.
4. 정렬된 구간을 먼저 찾고, target이 그 구간 안에 있는지를 판단하여 범위를 줄인다.
5. 탐색 종료 조건과 최종 반환값(left, right, mid 등)을 먼저 명확히 정한 뒤 구현한다.

특히 이번 문제를 통해 **이분 탐색은 단순히 `mid`를 계산하는 알고리즘이 아니라, "어떤 기준으로 탐색 범위를 절반으로 줄일 것인가"를 설계하는 알고리즘**이라는 점을 다시 한 번 느낄 수 있었다.

## 문제 2

### 문제 정보

- 문제명: Rotting Oranges
- 문제 링크: https://leetcode.com/problems/rotting-oranges/description/
- 사용한 알고리즘 / 자료구조: BFS, 큐

### 처음 접근 방식

오렌지가 없는 경우(0)는 무시하고, 썩은 오렌지가(2) 인접한 신선한 오렌지(1)를 썩게 만드는 최단 시간을 구하는 문제라고 판단했다.

백준의 바이러스나 프로그래머스의 게임 맵 최단거리와 비슷한 유형이라고 생각했고, bfs로 간단하게 구현해보고자 했다.


### 풀이 방법

- 우선 인접 탐색을 해야 되니까 dx, dy 격자를 만든다.
- 큐에 썩은 오렌지의 인덱스(x, y)를 넣고
- 신선한 오렌지의 경우 fresh로 카운트한다.
- !queue.isEmpty() && fresh > 0 조건으로 bfs를 돈다.
- 현재 큐의 사이즈를 통해 현존하는 썩은 오렌지 만큼 동서남북 방향으로 탐색하며 신선한 오렌지를 감염시킨다.
- 감염 시킨 경우 fresh--, grid[cx][cy]의 값을 2(감염값)로 바꿔주고, queue에 추가한다.
- 각 사이클마다 minutes를 카운팅한다.

### 어려웠던 지점

- 썩은 오렌지들을 어떻게 하나의 사이클로 감염시킬 것인지 정의하기가 어려웠다.


### 해결 방법

- 썩은 오렌지들을 모두 큐에 넣고, 현재 큐에 들어간 오렌지의 개수를 기준으로 반복해서 감염시키면 된다.
- 다만, 신선 오렌지의 개수를 모두 세고, 그 개수를 큐 반복의 조건으로 포함해야 한다. (그래야 더이상 감염시켜도 되지 않는다거나, 감염을 모두 시키려고 했지만 못 시키는 경우를 판정하고 루프를 나오거나 -1을 리턴할 수 있다.) 

### 시간복잡도 / 공간복잡도

- 시간복잡도: O(M x N)
- 공간복잡도: O(M x N)

## 문제 3

### 문제 정보

- 문제명: 여행 경로
- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43164
- 사용한 알고리즘 / 자료구조: 정렬, 백트래킹, DFS, ArrayList

### 처음 접근 방식

ICN부터 출발해서 알파벳 순으로 모든 도시를 방문하는 결과를 만들어서 리턴해야 되는 문제라고 판단했다.

알파벳 순으로 진행을 하지만, 모든 도시를 방문할 수 없다면 상태를 되돌려야 되기 때문에 백트래킹이라고 보았다.


### 풀이 방법

- 경로를 동적으로 추가하고, 삭제해야 되기에 ArrayList 경로 저장 용도로 전역 선언
- 방문을 위한 visited 배열, 검증을 위한 found 전역 선언 및 할당
- dfs를 통해 ICN부터 알파벳 순으로 돌되, 모든 도시 방문이 불가능할 때
```java
path.remove(path.size() - 1);

visited[i] = false;
```
- 를 통해서 백트래킹 적용
- dfs 반복마다 count + 해주며 티켓 수에 도달했을 때 return


### 어려웠던 지점

- 이차원 배열 안에서 알파벳 순으로 정렬 기준을 어떻게 구현해야 될지 바로 떠올리지 못했다.


### 해결 방법

간단하게 Arrays.sort에서 정렬 기준을 만들어주면 됐다.
```java
Arrays.sort(tickets, (a, b) -> {
        if (a[0].equals(b[0])) {
        return a[1].compareTo(b[1]);
    }
            return a[0].compareTo(b[0]);
});
```


### 시간복잡도 / 공간복잡도

- 시간복잡도: O(N * N!) -> 백트래킹 할 때 전체 순회(N) x 티켓의 모든 순서 순회 가능(N!)
- 공간복잡도: O(N)
