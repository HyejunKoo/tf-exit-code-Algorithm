## 문제 1

### 문제 정보

* 문제명: 땅따먹기
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12913
* 사용한 알고리즘 / 자료구조: DP, 2차원 배열

### 처음 접근 방식

각 행에서 가장 큰 점수를 고르면 된다고 생각했다. 하지만 바로 이전 행에서 같은 열을 선택할 수 없다는 조건 때문에, 현재 행의 최댓값만 보면 전체 최댓값을 보장할 수 없었다.

### 풀이 방법

1. `dp[i][j]`를 `i`번째 행에서 `j`번째 칸을 선택했을 때 얻을 수 있는 최대 점수로 정의한다.
2. 첫 번째 행은 그대로 초기값으로 둔다.
3. 두 번째 행부터는 현재 열 `j`와 같은 열을 제외한 이전 행의 값 중 최댓값을 찾는다.
4. `dp[i][j] = land[i][j] + max(dp[i - 1][k])` 형태로 갱신한다.
5. 마지막 행의 값 중 최댓값을 정답으로 반환한다.

### 어려웠던 지점

한 행씩 가장 큰 값만 선택하면 될 것처럼 보였지만, 이전 선택이 다음 행의 선택지를 제한한다는 점을 놓치기 쉬웠다.

또 현재 칸까지 왔을 때의 최댓값을 저장해야 하는데, 전체 최댓값 하나만 관리하면 어떤 열에서 끝났는지 알 수 없었다.

### 해결 방법

현재 행의 각 열마다 따로 최댓값을 저장했다. 이렇게 하면 다음 행에서 같은 열만 제외하고 이전까지의 최적 결과를 사용할 수 있었다.

열 개수가 4개로 고정되어 있으므로, 각 칸마다 다른 3개의 이전 값을 비교하는 방식으로 단순하게 처리했다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N)
* 공간복잡도: O(N)

`N`은 행의 개수이다. 열의 개수는 4개로 고정되어 있어서 상수로 볼 수 있다.

### 새롭게 알게 된 점

DP에서는 단순히 지금 가장 좋아 보이는 선택을 하는 것이 아니라, 현재 선택 이후에도 필요한 정보를 상태에 남겨야 한다. 이 문제에서는 "몇 번째 열을 골랐는지"가 다음 선택에 영향을 주는 핵심 상태였다.

## 문제 2

### 문제 정보

* 문제명: 정수 삼각형
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43105
* 사용한 알고리즘 / 자료구조: DP, 2차원 배열

### 처음 접근 방식

위에서부터 내려오면서 매번 더 큰 숫자가 있는 방향으로 이동하면 된다고 생각했다. 하지만 중간에서 큰 값을 고르는 것이 마지막까지의 최대 합으로 이어지지 않을 수 있었다.

### 풀이 방법

1. `dp[i][j]`를 삼각형의 `i`번째 줄 `j`번째 위치까지 내려왔을 때 만들 수 있는 최대 합으로 정의한다.
2. 맨 위 값은 `dp[0][0]`에 그대로 저장한다.
3. 왼쪽 끝 위치는 바로 위에서만 내려올 수 있으므로 `dp[i][0] = dp[i - 1][0] + triangle[i][0]`으로 갱신한다.
4. 오른쪽 끝 위치는 왼쪽 위에서만 내려올 수 있으므로 `dp[i][i] = dp[i - 1][i - 1] + triangle[i][i]`로 갱신한다.
5. 가운데 위치는 위쪽 두 칸 중 더 큰 값을 선택해 현재 값을 더한다.
6. 마지막 줄에서 가장 큰 값을 찾아 반환한다.

### 어려웠던 지점

가장자리와 가운데 위치의 이전 경로 개수가 달라서 인덱스 처리가 헷갈렸다.

특히 가운데 칸은 `j - 1`과 `j` 위치에서 내려올 수 있지만, 가장 왼쪽과 오른쪽은 선택지가 하나뿐이라 같은 점화식으로 처리하면 인덱스 오류가 날 수 있었다.

### 해결 방법

가장자리 조건을 먼저 분리하고, 가운데 칸에 대해서만 두 이전 값 중 큰 값을 고르도록 작성했다.

또 각 위치까지의 최대 합을 누적해서 저장하니, 마지막 줄에 도착했을 때 가능한 모든 경로의 최댓값을 한 번에 비교할 수 있었다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N^2)
* 공간복잡도: O(N^2)

`N`은 삼각형의 높이이다. 삼각형 안의 모든 숫자를 한 번씩 확인한다.

### 새롭게 알게 된 점

현재 위치까지 도달하는 방법이 여러 개일 때는, 그중 최적의 값을 저장해 다음 단계에서 재사용할 수 있다. DP 점화식을 세울 때는 현재 상태가 어떤 이전 상태들로부터 올 수 있는지 먼저 생각해야 한다.

## 문제 3

### 문제 정보

* 문제명: 등굣길
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42898
* 사용한 알고리즘 / 자료구조: DP, 2차원 배열, 경로 개수

### 처음 접근 방식

오른쪽과 아래쪽으로만 이동할 수 있으므로 BFS나 DFS로 모든 경로를 탐색하면 된다고 생각했다.

하지만 격자 크기가 커질수록 가능한 경로 수가 급격히 많아져서, 모든 경로를 직접 세는 방식은 시간초과가 날 수 있었다.

### 풀이 방법

1. `dp[y][x]`를 시작점에서 `(x, y)` 위치까지 올 수 있는 경로의 개수로 정의한다.
2. 물에 잠긴 지역은 이동할 수 없도록 따로 표시한다.
3. 시작점 `dp[1][1]`을 1로 초기화한다.
4. 격자를 왼쪽 위에서 오른쪽 아래 방향으로 순회한다.
5. 현재 칸이 물웅덩이라면 경로 개수를 0으로 두고 넘어간다.
6. 현재 칸까지 오는 경로 수는 위쪽 칸과 왼쪽 칸의 경로 수를 더한 값이다.
7. 값이 커질 수 있으므로 매번 `1,000,000,007`로 나눈 나머지를 저장한다.
8. 도착점 `dp[n][m]`을 반환한다.

### 어려웠던 지점

문제에서 좌표가 `(x, y)` 순서로 주어지는데, 배열에서는 보통 `[행][열]` 순서로 접근해서 헷갈릴 수 있었다.

또 물웅덩이가 있는 칸은 경로를 이어받으면 안 되기 때문에, DP 값을 갱신하기 전에 먼저 예외 처리를 해야 했다.

### 해결 방법

배열을 만들 때 `dp[y][x]` 기준으로 통일해서 좌표를 저장했다.

물웅덩이 칸은 `blocked[y][x]`처럼 따로 표시하고, 순회 중 해당 칸을 만나면 값을 더하지 않도록 처리했다. 시작점도 물웅덩이 처리에 영향을 받지 않도록 먼저 명확히 초기화했다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N * M)
* 공간복잡도: O(N * M)

`N`과 `M`은 격자의 세로와 가로 길이이다. 모든 칸을 한 번씩 확인한다.

### 새롭게 알게 된 점

경로 개수 문제는 모든 경로를 직접 탐색하지 않고, 각 칸까지 도달하는 경우의 수를 누적해서 구할 수 있다. 2차원 DP에서는 좌표 순서와 초기값, 이동 불가능한 칸 처리가 정답에 큰 영향을 준다.
