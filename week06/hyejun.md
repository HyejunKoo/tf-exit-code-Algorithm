# 오답노트

## 문제 1

* **문제명:** 연속 부분 수열 합의 개수
* **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/131701
* **알고리즘 / 자료구조:** 완전탐색, 누적 합, 집합

### 접근 및 시행착오

원형 수열이라 배열의 끝을 넘어가는 부분 수열을 어떻게 처리할지 헷갈렸다. 배열을 두 번 이어 붙이면 원형 구조를 일반 배열처럼 다룰 수 있다는 점을 이용했다.

### 최종 풀이

`elements`를 두 번 이어 붙인 배열의 누적 합을 구한다. 부분 수열의 길이를 1부터 전체 길이까지 늘려가며, 각 시작점에서의 합을 계산해 `set`에 저장한다. 마지막에 집합의 크기를 반환한다.

### 복잡도

* 시간복잡도: O(N²)
* 공간복잡도: O(N²)

### 핵심 포인트

원형 배열은 기존 배열을 두 번 이어 붙이면 인덱스 처리가 간단해진다. 중복을 제거하며 개수만 구할 때는 `set`을 사용하면 된다.

## 문제 2

* **문제명:** 영어 끝말잇기
* **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/12981
* **알고리즘 / 자료구조:** 시뮬레이션, 집합

### 접근 및 시행착오

끝말잇기 조건뿐만 아니라 중복된 단어도 함께 확인해야 했다. 탈락한 순서를 사람 번호와 차례로 바꾸는 계산에서 인덱스를 주의해야 했다.

### 최종 풀이

첫 번째 단어를 집합에 저장한 뒤 두 번째 단어부터 확인한다. 앞 단어의 마지막 글자와 현재 단어의 첫 글자가 다르거나, 이미 나온 단어라면 탈락이다.

탈락한 단어의 인덱스를 `i`라고 할 때 사람 번호는 `i % n + 1`, 차례는 `i // n + 1`로 구한다. 끝까지 문제가 없으면 `[0, 0]`을 반환한다.

### 복잡도

* 시간복잡도: O(M)
* 공간복잡도: O(M)

### 핵심 포인트

순서대로 진행되는 문제는 조건을 그대로 구현하면 된다. 0부터 시작하는 인덱스를 사람 번호와 차례로 변환할 때 나머지와 몫을 활용할 수 있다.

## 문제 3

* **문제명:** 예상 대진표
* **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/12985
* **알고리즘 / 자료구조:** 시뮬레이션

### 접근 및 시행착오

처음에는 각 라운드의 대진표를 직접 만들어야 한다고 생각했다. 하지만 다음 라운드의 참가자 번호가 현재 번호만으로 결정된다는 점을 이용하면 더 간단하게 풀 수 있었다.

### 최종 풀이

한 라운드가 끝날 때마다 참가자 번호를 `(번호 + 1) // 2`로 변경한다. A와 B의 번호가 같아질 때까지 반복하면서 라운드 수를 증가시킨다. 두 번호가 처음 같아진 시점이 두 참가자가 만난 라운드다.

### 복잡도

* 시간복잡도: O(log N)
* 공간복잡도: O(1)

### 핵심 포인트

토너먼트에서 다음 라운드의 번호는 `(현재 번호 + 1) // 2`로 계산할 수 있다. 대진표 전체를 직접 만들 필요 없이 참가자 번호만 갱신하면 된다.
