# 오답노트

## 문제 1

* **문제명:** 가장 가까운 같은 글자
* **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/142086
* **알고리즘 / 자료구조:** 해시(HashMap)

### 접근 및 시행착오

처음에는 map의 value에 이전에 나온 문자와의 거리를 계산해서 넣어야 하나 생각했다.

하지만 거리를 저장하면 다음에 같은 문자가 나왔을 때 가장 가까운 문자의 위치를 알 수 없다.

따라서 map에는 각 문자가 마지막으로 등장한 위치(index)​를 저장하고, 같은 문자를 다시 만날 때마다 현재 위치로 갱신하는 방식으로 접근해야 한다.

### 최종 풀이

1. map의 key에는 문자를, value에는 해당 문자가 마지막으로 등장한 위치를 저장한다.
2. 문자열을 순회하면서 map.containsKey(c)를 통해 현재 문자가 이전에 나온 적이 있는지 확인한다.
3. 처음 나온 문자라면 answer[i] = -1을 저장한다.
4. 이전에 나온 문자라면 현재 위치(i) - 이전 위치(map.get(c))를 계산하여 answer[i]에 저장한다.
5. 계산이 끝난 후 map.put(c, i)를 통해 해당 문자의 마지막 위치를 현재 위치로 갱신한다.

### 복잡도

* 시간복잡도: O(N)
* 공간복잡도: O(N)


### 핵심 포인트

- HashMap의 value에는 거리가 아니라 마지막으로 등장한 위치를 저장한다.
- 거리 계산이 끝난 후 반드시 현재 위치로 갱신해야 한다.
- 특정 값의 최근 위치를 기억해야 하는 문제에서는 HashMap<값, 마지막 위치> 형태를 떠올린다.

## 문제 2

* **문제명:** 신고 결과 받기
* **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/92334
* **알고리즘 / 자료구조:** 해시(HashMap, HashSet)

### 접근 및 시행착오

중복 신고를 제거하기 위해 HashSet을 사용하고, HashMap을 통해 각 사용자가 신고당한 횟수를 카운팅해야 한다는 생각까지는 했다.
하지만 신고자별 메일 횟수를 answer 배열에 저장하기 위해 사용자 ID와 answer 배열의 인덱스를 연결해야 한다는 점은 처음에 고려하지 못했다.
이를 해결하기 위해 사용자 ID → 인덱스를 저장하는 HashMap을 추가로 사용했다.

(다른 사람의 풀이를 살펴보니 직접 User 클래스를 만들어 사용자별 정보를 관리하는 방법도 있었고, 같은 문제라도 데이터를 관리하는 방법이 다양할 수 있다는 것을 알게 되었다.)


### 최종 풀이
1. 중복 신고 제거를 위한 HashSet, 신고당한 횟수를 저장할 HashMap, 사용자 ID와 answer 배열의 인덱스를 연결할 HashMap을 선언한다.
2. report 배열을 순회하며 HashSet에 저장하여 동일한 사용자의 중복 신고를 제거한다.
3. id_list를 순회하며 HashMap에 사용자 ID → 인덱스를 저장한다. 해당 인덱스는 answer 배열에서 사용자의 위치를 의미한다.
4. 중복이 제거된 HashSet을 순회한다. 신고 정보를 split()하여 신고당한 사용자를 구하고, countMap에 신고당한 횟수를 저장한다.
5. HashSet을 다시 순회하며 split()하여 신고자와 신고당한 사용자를 구한다. 신고당한 사용자의 신고 횟수가 k 이상이면 신고자의 answer 값을 1 증가시킨다.


### 복잡도

* 시간복잡도: O(N + R)
- N: id_list의 길이
- R: report의 길이
* 공간복잡도: O(N + R)

### 핵심 포인트

- 배열의 위치를 사용자 ID로 자주 찾아야 한다면 사용자 ID → index 형태의 HashMap을 만들어 빠르게 조회할 수 있다.
- 같은 문제라도 여러 HashMap으로 정보를 나누어 관리하거나 별도의 User 클래스로 묶어서 관리하는 등 다양한 방법으로 모델링할 수 있다.

## 문제 3

* **문제명:** 숫자 짝꿍
* **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/131128
* **알고리즘 / 자료구조:** 해시, 배열

### 접근 및 시행착오
처음에는 공통으로 등장하는 숫자를 어떻게 찾아야 할지 접근 방식이 잘 떠오르지 않아 GPT의 도움을 받아 풀었다.

해시 문제를 주로 풀다 보니 처음에는 HashMap으로 접근했다. 이후에는 숫자가 0~9로 한정되어 있기 때문에 HashMap 대신 int[10] 배열을 사용하면 더 단순하게 풀 수 있다는 것도 알게 되었다.

또한 입력 문자열의 길이가 최대 300만이기 때문에 결과 문자열을 반복해서 연결할 때 String의 += 연산보다 StringBuilder를 사용해야 효율적이라는 점을 배웠다.

### 최종 풀이

1. X 문자열을 순회하면서 각 숫자의 등장 횟수를 HashMap<Character, Integer>에 저장한다. (Y 문자열도 동일)
2. 9'부터 '0'까지 역순으로 순회한다.
3. 각 숫자에 대해 Math.min(xCnt, yCnt)으로 X와 Y에서 서로 짝지을 수 있는 개수를 구한다.
4. 짝지을 수 있는 개수만큼 해당 숫자를 StringBuilder에 추가한다.
5. 결과의 길이가 0이면 공통 숫자가 없으므로 "-1"을 반환한다.
6. 결과의 첫 번째 문자가 '0'이면 공통 숫자가 0으로만 구성된 것이므로 "0"을 반환한다.
7. 나머지 경우 완성된 문자열을 반환한다.

### 복잡도

* 시간복잡도: O(|X| + |Y|) 
* 공간복잡도: O(|answer|)

### 핵심 포인트

- 결과 문자열의 길이가 매우 클 수 있으므로 String의 += 연산 대신 StringBuilder.append()를 사용한다. String은 불변 객체라 반복적인 문자열 연결 시 새로운 객체가 계속 생성되어 비효율적이다.
