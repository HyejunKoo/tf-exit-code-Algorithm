## 문제 1

### 문제 정보

* 문제명: 미로 탈출
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/159993
* 사용한 알고리즘 / 자료구조: BFS, 큐, 2차원 배열

### 처음 접근 방식

레버를 당긴 뒤 출구로 가야 하는 문제라서, "레버를 당겼는가"를 상태로 들고 다녀야 한다고 생각했다. 그래서 `visited`를 `[n][m][2]`로 만들고 레버 통과 여부를 세 번째 차원에 넣어 한 번의 BFS로 끝내려고 했다. 구현은 됐는데 코드가 생각보다 지저분해졌고, 레버 칸을 지나갈 때 상태를 바꾸는 부분에서 계속 실수했다.

### 풀이 방법

1. 맵을 훑어서 시작 위치 `S`, 레버 위치 `L`, 출구 위치 `E`의 좌표를 미리 찾아둔다.
2. 시작점과 도착점을 받아 최단거리를 반환하는 BFS 함수를 하나만 만든다. 도달하지 못하면 `-1`을 반환한다.
3. BFS 안에서는 방문 배열을 새로 만들고 상하좌우 네 방향을 확인한다. 맵 밖이거나 벽(`X`)이거나 이미 방문한 칸이면 건너뛴다.
4. `S → L` 거리와 `L → E` 거리를 각각 구한다.
5. 둘 중 하나라도 `-1`이면 탈출이 불가능하므로 `-1`을 반환하고, 아니면 두 거리를 더해서 반환한다.

### 어려웠던 지점

상태를 하나 더 붙이는 방식에 먼저 손이 갔던 게 문제였다. 레버 칸에 도착한 순간 상태를 1로 바꿔야 하는데, 큐에 넣을 때 바꿀지 꺼낼 때 바꿀지 헷갈려서 같은 칸이 두 상태로 중복 탐색되거나 반대로 누락됐다. 그리고 레버를 거치지 않고 출구에 먼저 닿은 경로를 답으로 잘못 반환한 적도 있었다.

### 해결 방법

"레버를 반드시 거쳐야 한다"는 건 경로가 `S → L`과 `L → E` 두 구간으로 완전히 쪼개진다는 뜻이었다. 레버에 도착하기 전과 후는 서로 영향을 주지 않고, 레버 지점을 다시 밟는 게 이득일 수도 없다. 그래서 상태 차원을 없애고 BFS를 두 번 따로 돌리는 방식으로 바꿨다. 함수 하나를 재사용하니 코드도 절반으로 줄고 디버깅도 쉬워졌다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N * M)
* 공간복잡도: O(N * M)

`N`, `M`은 맵의 세로, 가로 길이(각각 최대 100)이다. BFS를 두 번 돌리지만 상수 배이므로 그대로 `O(N * M)`이다.

### 새롭게 알게 된 점

경유지가 정해져 있는 최단경로 문제는 상태를 추가하는 대신 구간을 나눠서 BFS를 여러 번 돌리는 쪽이 훨씬 간단하다. 반대로 경유지를 "들를 수도 있고 안 들를 수도 있는" 선택지로 줄 때는 상태 차원이 필요하다. 이 둘을 구분하는 기준이 "경유가 강제인가"라는 걸 이제 알게 됐다.

## 문제 2

### 문제 정보

* 문제명: 경주로 건설
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/67259
* 사용한 알고리즘 / 자료구조: 상태 BFS / 다익스트라, 우선순위 큐, 3차원 dist 배열

### 처음 접근 방식

격자 최단경로니까 지난주처럼 BFS로 칸 수만 세면 될 거라 생각했다. 그런데 직선은 100원, 코너는 500원이라 비용이 칸마다 다르고, 같은 칸이라도 어느 방향으로 들어왔는지에 따라 다음 비용이 달라졌다. 그걸 무시하고 `dist[y][x]` 하나만 관리했더니 처음 방문할 때의 값으로 칸이 고정돼서 계속 틀렸다.

### 풀이 방법

1. `dist`를 `[N][N][4]`로 만들고 무한대로 초기화한다. 세 번째 차원은 그 칸에 들어온 방향(위/아래/왼/오른)이다.
2. 시작 칸 `(0, 0)`에서 오른쪽과 아래쪽으로 각각 출발하는 두 상태를 비용 0으로 큐에 넣는다.
3. 큐에서 비용이 가장 작은 `(비용, y, x, 방향)`을 꺼낸다. 저장된 `dist` 값보다 크면 지나간 정보이므로 무시한다.
4. 네 방향으로 이동을 시도한다. 격자 밖이거나 벽(`1`)이면 건너뛴다.
5. 새 비용은 이전 방향과 같으면 `+100`, 다르면 `+600`(직선 100 + 코너 500)으로 계산한다.
6. 계산한 값이 `dist[ny][nx][새 방향]`보다 작을 때만 갱신하고 큐에 넣는다.
7. 마지막에 `dist[N-1][N-1]`의 네 방향 값 중 최솟값을 반환한다.

### 어려웠던 지점

방향을 상태에 넣지 않은 게 첫 번째 실수였다. 그래서 코너를 한 번 더 돌더라도 나중에 직선으로 쭉 뻗는 게 더 싼 경로를 놓쳤다. 두 번째는 도착 칸의 답을 `dist[N-1][N-1][0]`처럼 방향 하나만 보고 반환한 것이고, 세 번째는 시작 칸에서 방향을 정해주지 않아 첫 이동이 무조건 코너로 계산된 것이었다.

### 해결 방법

"같은 칸이라도 들어온 방향이 다르면 다른 지점"으로 보기로 하고 `dist`에 방향 차원을 추가했다. 그러면 노드가 `N * N * 4`개인 그래프의 일반적인 최단경로 문제가 되고, 간선 비용이 100과 600 두 종류이므로 우선순위 큐를 쓰는 다익스트라가 그대로 들어맞았다. 시작 칸은 아직 방향이 없으니 오른쪽·아래쪽 두 경우를 모두 비용 0으로 넣어 출발시켰고, 답은 도착 칸의 네 방향 중 최솟값으로 가져왔다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N² log N)
* 공간복잡도: O(N²)

노드 수가 `N * N * 4`, 각 노드에서 나가는 간선이 4개이므로 간선 수도 `N²`에 비례한다. `N`은 최대 25로 작다.

### 새롭게 알게 된 점

최단경로 문제에서 "지금까지 어떻게 왔는지"가 다음 비용에 영향을 주면, 그 정보를 상태에 넣어 노드를 쪼개야 한다. 좌표만으로 노드를 잡으면 최적해를 놓친다. 이번엔 방향이었지만 남은 연료, 사용한 아이템 개수, 벽을 부순 횟수 같은 것도 똑같은 방식으로 차원을 늘려 처리할 수 있다는 걸 알게 됐다.

## 문제 3

### 문제 정보

* 문제명: 부대복귀
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/132266
* 사용한 알고리즘 / 자료구조: BFS, 인접 리스트, 역방향 탐색

### 처음 접근 방식

여러 부대원이 각자 다른 지역에서 목적지로 돌아가야 하니, `sources`에 있는 지역마다 BFS를 한 번씩 돌려서 `destination`까지의 거리를 구하려고 했다. 예제는 통과했지만 `sources`가 길어지는 케이스에서 시간초과가 났다.

### 풀이 방법

1. 도로 정보를 양방향 인접 리스트로 저장한다.
2. `dist` 배열을 `-1`로 초기화하고, `destination` 한 곳만 `0`으로 두고 큐에 넣는다.
3. 큐에서 지역을 하나 꺼내 연결된 지역들을 확인한다.
4. 아직 `-1`인 지역만 `dist[현재] + 1`로 채우고 큐에 넣는다.
5. 탐색이 끝나면 `sources`를 순서대로 돌면서 `dist[s]` 값을 모아 반환한다. 도달할 수 없는 지역은 `-1`이 그대로 남는다.

### 어려웠던 지점

출발지가 여러 개라는 것만 보고 출발지마다 탐색을 돌리는 그림에서 벗어나지 못했다. 지역 수와 도로 수가 둘 다 크고 `sources`도 길어서, BFS 자체는 빠른데 그걸 `sources` 개수만큼 반복하는 순간 비용이 곱해졌다. 결과 배열 순서를 `sources` 입력 순서와 맞춰야 한다는 것도 놓쳐서 한 번 틀렸다.

### 해결 방법

목적지는 하나인데 출발지가 여러 개이므로, 탐색 방향을 뒤집어서 `destination`에서 한 번만 BFS를 돌렸다. 도로가 양방향이라 `destination → s` 거리와 `s → destination` 거리가 같으니 결과는 그대로 쓸 수 있었다. 이렇게 하면 `sources`가 몇 개든 탐색은 한 번으로 끝난다. 반환할 때는 `sources`를 순회하며 `dist`를 찾아 담아 입력 순서를 유지했다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(V + E)
* 공간복잡도: O(V + E)

`V`는 지역 수(최대 100,000), `E`는 도로 수(최대 500,000)이다. `sources`의 길이와 무관하게 탐색은 한 번만 수행한다.

### 새롭게 알게 된 점

지난주 등산코스 문제는 출발지가 여러 개, 도착지가 여러 개여서 출발지를 모두 큐에 넣는 다중 시작점 방식을 썼는데, 이번엔 도착지가 하나라서 방향을 뒤집는 쪽이 답이었다. 출발지가 많고 도착지가 하나면 역방향으로 한 번, 출발지가 하나고 도착지가 많으면 정방향으로 한 번 돌리면 된다. 어느 쪽이 하나인지를 먼저 확인하는 습관을 들여야겠다.
