## 문제 1

### 문제 정보

* 문제명: 게임 맵 최단거리
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/1844
* 사용한 알고리즘 / 자료구조: BFS, Queue, 2차원 배열

### 처음 접근 방식

시작 지점에서 도착 지점까지 갈 수 있는 모든 경로를 DFS로 탐색하면서 가장 짧은 거리를 갱신하려고 했다.

### 풀이 방법

1. 이동할 수 있는 방향을 상, 하, 좌, 우 네 방향으로 정의한다.
2. 시작 위치 `(0, 0)`을 큐에 넣고 방문 처리한다.
3. 큐에서 현재 위치를 하나씩 꺼낸다.
4. 현재 위치에서 네 방향으로 이동할 수 있는지 확인한다.
5. 맵 범위 안에 있고, 벽이 아니며, 아직 방문하지 않은 칸이면 이동한다.
6. 다음 칸의 거리는 현재 칸의 거리에서 1을 더해 저장한다.
7. 도착 지점에 도달하면 해당 위치에 저장된 거리를 반환한다.
8. 탐색이 끝났는데 도착 지점에 도달하지 못했다면 `-1`을 반환한다.

### 어려웠던 지점

최단거리를 구해야 해서 DFS로 모든 경로를 탐색하면 답은 구할 수 있지만, 같은 칸을 여러 번 방문하면서 비효율이 커질 수 있었다.

### 해결 방법

가중치가 없는 격자에서 최단거리를 구할 때는 BFS를 사용해야 한다는 점을 적용했다.

BFS는 시작점에서 가까운 칸부터 차례대로 방문하므로, 어떤 칸에 처음 도착했을 때의 거리가 곧 최단거리이다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N * M)
* 공간복잡도: O(N * M)

### 새롭게 알게 된 점

가중치가 없는 그래프나 격자에서 최단거리를 구하는 문제는 BFS로 접근하는 것이 적합하다. 방문 배열을 따로 만들 수도 있지만, 기존 `maps` 배열에 거리를 누적해서 저장하면 방문 처리와 거리 계산을 함께 할 수 있다.

## 문제 2

### 문제 정보

* 문제명: 단어 변환
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43163
* 사용한 알고리즘 / 자료구조: BFS, Queue, 문자열 비교, 방문 배열

### 처음 접근 방식

현재 단어에서 한 글자만 다른 단어를 계속 찾아가면 된다고 생각했지만, 어떤 단어를 먼저 선택해야 최소 변환 횟수가 되는지 판단하기 어려웠다.

### 풀이 방법

1. `target`이 `words` 안에 없다면 변환할 수 없으므로 바로 `0`을 반환한다.
2. 시작 단어 `begin`과 변환 횟수 `0`을 큐에 넣는다.
3. 큐에서 현재 단어와 현재까지의 변환 횟수를 꺼낸다.
4. 현재 단어가 `target`과 같다면 변환 횟수를 반환한다.
5. `words`를 순회하면서 아직 방문하지 않은 단어를 확인한다.
6. 현재 단어와 비교했을 때 다른 글자의 개수가 정확히 1개인 단어만 다음 후보로 선택한다.
7. 선택한 단어를 방문 처리하고, 변환 횟수를 1 증가시켜 큐에 넣는다.
8. 큐가 빌 때까지 `target`에 도달하지 못하면 `0`을 반환한다.

### 어려웠던 지점

단어를 하나씩 바꿔가는 과정이 경로 탐색이라는 점은 보였지만, 최소 횟수를 보장하려면 어떤 탐색 방식을 사용해야 하는지 헷갈렸다.

### 해결 방법

단어 하나를 정점으로 보고, 한 글자만 다른 단어 사이에 간선이 있다고 생각했다.

한 번 변환하는 비용이 모두 1로 같기 때문에 BFS를 사용하면 가장 적은 변환 횟수를 먼저 찾을 수 있다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N^2 * L)
* 공간복잡도: O(N)

`N`은 단어의 개수, `L`은 단어의 길이이다.

### 새롭게 알게 된 점

문자열 문제도 조건에 따라 그래프로 바꿔서 생각할 수 있다. 한 상태에서 다른 상태로 이동하는 비용이 동일하다면 BFS를 사용해 최소 이동 횟수를 구할 수 있다.

## 문제 3

### 문제 정보

* 문제명: 여행경로
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43164
* 사용한 알고리즘 / 자료구조: DFS, Backtracking, 정렬, 방문 배열

### 처음 접근 방식

출발지가 `ICN`인 항공권부터 차례대로 선택하면서 갈 수 있는 공항을 이어 붙이면 된다고 생각했다.

### 풀이 방법

1. 가능한 경로가 여러 개일 때 알파벳 순서가 앞서는 경로를 반환해야 하므로 항공권을 도착지 기준으로 정렬한다.
2. 항상 `ICN`에서 시작하므로 경로 배열에 `ICN`을 먼저 넣는다.
3. 현재 공항에서 출발할 수 있고 아직 사용하지 않은 항공권을 찾는다.
4. 해당 항공권을 사용 처리하고 도착 공항을 경로에 추가한다.
5. 다음 공항을 기준으로 다시 DFS를 수행한다.
6. 사용한 항공권 수가 전체 항공권 수와 같아지면 모든 티켓을 사용한 경로이므로 정답으로 반환한다.
7. 진행 중 더 이상 사용할 수 있는 항공권이 없다면, 마지막 공항을 경로에서 제거하고 항공권 사용 처리를 되돌린다.
8. 정렬된 순서대로 DFS를 수행하므로 처음 완성되는 경로가 알파벳 순서가 가장 앞서는 경로이다.

### 어려웠던 지점

눈앞에서 알파벳 순서가 가장 빠른 도착지를 고르는 것이 항상 전체 경로의 정답이 되는지 확신하기 어려웠다.

특히 같은 출발지와 도착지를 가진 항공권이 여러 개 있을 수 있어서, 공항 이름만으로 방문 여부를 처리하면 안 된다는 점도 주의해야 했다.

### 해결 방법

항공권 자체를 각각 하나의 간선으로 보고, 티켓 인덱스를 기준으로 방문 여부를 관리했다.

경로가 막히면 방금 선택한 항공권과 공항을 되돌리는 백트래킹을 사용해 모든 티켓을 정확히 한 번씩 쓰는 경로만 인정했다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: 최악의 경우 O(E! * E)
* 공간복잡도: O(E)

`E`는 항공권의 개수이다.

### 새롭게 알게 된 점

DFS는 단순히 깊게 탐색하는 데만 쓰이는 것이 아니라, 선택을 되돌리면서 조건을 만족하는 전체 경로를 찾는 백트래킹 문제에도 사용할 수 있다.

중복될 수 있는 값이 있을 때는 값 자체가 아니라 입력의 인덱스처럼 각 원소를 구분할 수 있는 기준으로 방문 처리를 해야 한다.
