# 오답노트

## 문제 1

- **문제명:** Top K Frequent Elements
- **문제 링크:** https://neetcode.io/problems/top-k-elements-in-list/question?list=neetcode150
- **알고리즘 / 자료구조:** 해시맵, 정렬

### 접근 및 시행착오

배열에서 가장 자주 등장한 숫자 `k`개를 반환해야 하는 문제였다. 각 숫자가 몇 번 등장했는지 알아야 하므로, 먼저 숫자를 key로 하고 등장 횟수를 value로 하는 HashMap을 사용하면 된다고 생각했다.

처음에는 모든 숫자를 직접 비교하는 방식도 생각할 수 있지만, 중복된 숫자의 개수를 효율적으로 세기 위해 HashMap을 사용했다. 이후 등장 횟수를 기준으로 숫자들을 정렬하면 빈도가 높은 순서대로 값을 뽑을 수 있다.

### 최종 풀이

먼저 `nums` 배열을 순회하면서 각 숫자의 등장 횟수를 HashMap에 저장했다.

```java
map.put(nums[i], map.getOrDefault(nums[i], 0) + 1);
```

그 다음 HashMap의 key들을 리스트로 변환했다. 리스트에는 중복이 제거된 숫자들만 들어 있다. 이후 각 숫자의 등장 횟수를 기준으로 내림차순 정렬했다.

```java
list.sort((a, b) -> map.get(b) - map.get(a));
```

정렬이 끝나면 리스트의 앞쪽에는 등장 횟수가 높은 숫자들이 오므로, 앞에서부터 `k`개를 결과 배열에 담아 반환했다.

### 복잡도

- 시간복잡도: O(n log n)
- 공간복잡도: O(n)

정확히는 서로 다른 숫자의 개수를 `m`이라고 하면 HashMap 생성은 O(n), 정렬은 O(m log m)이다. 최악의 경우 `m`이 `n`과 같을 수 있으므로 전체 시간복잡도는 O(n log n)이다.

### 핵심 포인트

빈도 계산이 필요한 문제에서는 HashMap을 먼저 떠올릴 수 있다. 이 풀이에서는 등장 횟수를 세고, 빈도 기준으로 정렬해 상위 `k`개를 선택했다. 더 최적화한다면 PriorityQueue나 Bucket Sort를 활용할 수도 있다.

## 문제 2

- **문제명:** Encode and Decode Strings
- **문제 링크:** https://neetcode.io/problems/string-encode-and-decode/question?list=neetcode150
- **알고리즘 / 자료구조:** 문자열, 파싱, 구현

### 접근 및 시행착오

문자열 리스트를 하나의 문자열로 인코딩한 뒤, 다시 원래 리스트로 복원해야 하는 문제였다. 단순히 쉼표나 특정 구분자를 넣는 방식은 원본 문자열 안에 같은 구분자가 포함될 수 있기 때문에 안전하지 않다고 생각했다.

그래서 각 문자열 앞에 문자열의 길이를 함께 저장하면, 디코딩할 때 어디까지가 하나의 문자열인지 정확히 알 수 있다고 판단했다.

### 최종 풀이

인코딩할 때는 각 문자열을 다음과 같은 형식으로 이어 붙였다.

```text
문자열길이#문자열
```

예를 들어 `"hello"`는 `5#hello` 형태가 된다. 문자열 길이를 먼저 기록하고 `#`을 구분자로 넣은 뒤 실제 문자열을 붙였다.

디코딩할 때는 현재 위치 `i`에서부터 `#`이 나오는 위치를 찾았다. `#` 앞부분은 문자열의 길이를 의미하므로 정수로 변환했다.

```java
int hashIdx = str.indexOf('#', i);
int length = Integer.parseInt(str.substring(i, hashIdx));
```

그 다음 `hashIdx + 1`부터 `length`만큼 잘라 원래 문자열을 복원했다. 복원한 문자열을 결과 리스트에 추가하고, 다음 문자열의 시작 위치로 인덱스를 이동했다.

### 복잡도

- 시간복잡도: O(n)
- 공간복잡도: O(n)

여기서 `n`은 인코딩된 전체 문자열의 길이 또는 모든 원본 문자열 길이의 합이다. 문자열을 한 번씩 이어 붙이고, 디코딩할 때도 앞에서부터 순서대로 파싱하므로 선형 시간에 처리할 수 있다.

### 핵심 포인트

문자열을 하나로 합칠 때 단순 구분자만 사용하면 원본 문자열에 구분자가 포함되는 경우 문제가 생길 수 있다. 따라서 `길이 + 구분자 + 문자열` 형식으로 저장하면 문자열 안에 어떤 문자가 포함되어 있어도 안전하게 복원할 수 있다.

## 문제 3

- **문제명:** Product of Array Except Self
- **문제 링크:** https://neetcode.io/problems/products-of-array-discluding-self/question?list=neetcode150
- **알고리즘 / 자료구조:** 배열, Prefix Product, Postfix Product

### 접근 및 시행착오

각 위치마다 자기 자신을 제외한 나머지 숫자들의 곱을 구해야 하는 문제였다. 단순하게 매번 전체 배열을 다시 순회하면 O(n²)이 되기 때문에 비효율적이라고 생각했다.

나눗셈을 사용하지 않고 풀어야 하므로, 현재 위치의 왼쪽에 있는 값들의 곱과 오른쪽에 있는 값들의 곱을 따로 구해 곱하면 된다고 접근했다.

### 최종 풀이

먼저 왼쪽에서 오른쪽으로 순회하면서 현재 인덱스 기준 왼쪽 값들의 누적 곱을 `result[i]`에 저장했다.

```java
int prefix = 1;
for (int i = 0; i < nums.length; i++) {
    result[i] = prefix;
    prefix *= nums[i];
}
```

이후 오른쪽에서 왼쪽으로 다시 순회하면서 현재 인덱스 기준 오른쪽 값들의 누적 곱을 `postfix`로 관리했다. 그리고 기존에 저장해둔 왼쪽 누적 곱에 오른쪽 누적 곱을 곱했다.

```java
int postfix = 1;
for (int i = n - 1; i >= 0; i--) {
    result[i] *= postfix;
    postfix *= nums[i];
}
```

이렇게 하면 `result[i]`에는 `i`번째 값을 제외한 왼쪽 전체 곱과 오른쪽 전체 곱이 함께 반영된다.

### 복잡도

- 시간복잡도: O(n)
- 공간복잡도: O(1)

결과 배열을 제외하면 `prefix`, `postfix` 변수만 추가로 사용하므로 추가 공간복잡도는 O(1)이다. 단, 반환해야 하는 결과 배열까지 포함하면 O(n) 공간을 사용한다.

### 핵심 포인트

자기 자신을 제외한 전체 곱은 `왼쪽 누적 곱 × 오른쪽 누적 곱`으로 나눠서 생각할 수 있다. Prefix와 Postfix를 이용하면 나눗셈 없이도 O(n)에 문제를 해결할 수 있다.
