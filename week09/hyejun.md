# 오답노트

## 문제 1

- **문제명:** 피로도
- **문제 링크:** 프로그래머스 Lv.2
- **알고리즘 / 자료구조:** 완전탐색 (순열)

### 접근 및 시행착오

처음엔 그리디하게 "최소 필요 피로도" 낮은 순으로 도는 게 맞나 싶어서 정렬부터 했는데, 반례가 바로 떠올랐다. 소모 피로도까지 고려하면 순서에 따라 최대로 돌 수 있는 던전 수가 달라져서 그리디로는 안 풀리는 문제였다. 결국 던전 개수가 최대 8개밖에 안 된다는 제한사항 보고 "아 이건 그냥 다 돌려봐도 되는 규모구나" 하고 순열로 방향 잡음. 처음에 itertools 안 쓰고 재귀로 직접 순열 만들려다가 시간 아까워서 그냥 permutations로 바꿨당

### 최종 풀이

1. dungeons를 permutations로 모든 순서 조합 생성
2. 각 순서마다 현재 피로도(k)에서 시작해서 순서대로 "최소 필요 피로도" 체크
3. 조건 만족하면 소모 피로도만큼 차감하고 카운트 증가, 아니면 그냥 스킵(패스)
4. 각 순열에서 나온 카운트 중 최댓값 저장

```python
from itertools import permutations

def solution(k, dungeons):
    answer = 0
    for perm in permutations(dungeons):
        fatigue = k
        count = 0
        for need, cost in perm:
            if fatigue >= need:
                fatigue -= cost
                count += 1
        answer = max(answer, count)
    return answer
```

### 복잡도

- 시간복잡도: O(n! * n) — n ≤ 8이라 최대 8! = 40320이라 넉넉함
- 공간복잡도: O(n)

### 핵심 포인트

제한사항에 있는 숫자가 작으면(N ≤ 10 정도) 일단 완전탐색/순열/조합부터 의심해보기. 괜히 최적화된 그리디/DP 찾으려고 시간 쓰지 말고 규모부터 보는 습관 들이자.

## 문제 2

- **문제명:** 의상
- **문제 링크:** 프로그래머스 Lv.2
- **알고리즘 / 자료구조:** 해시(딕셔너리)

### 접근 및 시행착오

처음엔 종류별로 조합 다 뽑아서 더하는 식으로 접근하려다가 종류 개수가 늘어나면 경우의 수 계산이 복잡해질 것 같아서 멈췄다. "종류별로 (안 입음 포함) 경우의 수를 곱하고 마지막에 아무것도 안 입은 경우 1가지를 빼주면 되지 않을까" 하는 생각이 딱 떠올랐는데, 이게 맞는 풀이였음. 결국 핵심은 종류별 개수 세는 것부터 시작.

### 최종 풀이

1. defaultdict로 옷 종류별 개수 카운트
2. 각 종류마다 (해당 종류 옷 개수 + 1)을 answer에 곱함 → +1은 "그 종류를 안 입는 경우"
3. 마지막에 "아무것도 안 입는 경우" 1가지를 빼줌 (문제에서 최소 1개는 입어야 하니까)

```python
from collections import defaultdict

def solution(clothes):
    counter = defaultdict(int)
    for name, kind in clothes:
        counter[kind] += 1

    answer = 1
    for cnt in counter.values():
        answer *= (cnt + 1)

    return answer - 1
```

### 복잡도

- 시간복잡도: O(n) — clothes 순회 한 번, counter 순회 한 번
- 공간복잡도: O(k) — k는 옷 종류 개수

### 핵심 포인트

"조합의 수 구하기" 문제에서 "선택 안 함"까지 경우의 수에 포함시키고 나중에 빼는 트릭 기억해두기. 조합/부분집합 세는 문제 나오면 (개수+1) 곱셈 패턴 떠올리면 좋을 듯.

## 문제 3

- **문제명:** H-Index
- **문제 링크:** 프로그래머스 Lv.2
- **알고리즘 / 자료구조:** 정렬

### 접근 및 시행착오

H-Index 정의 자체가 처음엔 헷갈렸다. "h번 이상 인용된 논문이 h편 이상"이라는 조건을 어떻게 코드로 옮길지 감이 안 와서 예시 손으로 하나씩 따라가봄. 내림차순 정렬해서 인덱스랑 비교하면 되겠다 싶었는데, 처음에 인덱스를 0부터 세는 바람에 조건이 계속 틀려서 +1 안 해주고 헤맨 시간이 좀 있었다.

### 최종 풀이

1. citations를 내림차순 정렬
2. 인덱스(0부터 시작)를 idx라고 할 때, (idx+1)번째 논문까지는 최소 (idx+1)번 이상 인용된 상태
3. citations[idx] >= idx+1 을 만족하는 가장 큰 idx+1 값을 answer로 갱신

```python
def solution(citations):
    citations.sort(reverse=True)
    answer = 0
    for idx, c in enumerate(citations):
        if c >= idx + 1:
            answer = idx + 1
    return answer
```

### 복잡도

- 시간복잡도: O(n log n) — 정렬이 제일 오래 걸림
- 공간복잡도: O(1) (정렬은 in-place로)

### 핵심 포인트

정의가 헷갈리는 문제는 무조건 손으로 예시 따라가면서 인덱스 관계부터 확인하기. 특히 "몇 번째" 같은 표현 나오면 0-index vs 1-index 헷갈리기 쉬우니 +1 붙여야 하는지 항상 체크.
