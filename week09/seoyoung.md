## 문제 1

### 문제 정보

* 문제명: 배달
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12978
* 사용한 알고리즘 / 자료구조: 다익스트라, 우선순위 큐, 인접 리스트

### 처음 접근 방식

모든 마을 쌍 사이의 최단 거리를 완전탐색으로 다 구해보면 된다고 생각했다. 하지만 마을 수와 도로 수가 늘어나면 모든 경로를 직접 탐색하는 방식은 시간초과가 날 수밖에 없었다.

### 풀이 방법

1. 마을과 도로 정보를 인접 리스트로 저장한다. 같은 두 마을을 잇는 도로가 여러 개 주어질 수 있으므로 전부 리스트에 추가한다.
2. 시작 마을(1번)에서 각 마을까지의 최단 시간을 저장할 `dist` 배열을 무한대로 초기화하고, 시작 마을만 0으로 둔다.
3. `(거리, 노드)` 쌍을 우선순위 큐에 넣고, 거리가 가장 짧은 노드부터 꺼내며 탐색한다.
4. 꺼낸 거리가 이미 저장된 `dist` 값보다 크면 지나간 정보이므로 무시한다.
5. 인접한 마을로 가는 새로운 거리가 기존 `dist` 값보다 작으면 갱신하고 큐에 다시 넣는다.
6. 모든 탐색이 끝나면 `dist` 값이 K 이하인 마을의 개수를 세어 반환한다.

### 어려웠던 지점

같은 두 마을 사이에 여러 도로가 존재할 수 있다는 조건 때문에, 그래프를 만들 때 더 짧은 도로만 남겨야 하는지 헷갈렸다.

### 해결 방법

굳이 미리 최소 도로만 걸러낼 필요 없이, 모든 도로를 인접 리스트에 그대로 넣고 다익스트라 알고리즘 자체가 더 짧은 거리만 갱신하도록 맡기면 자연스럽게 해결됐다. 우선순위 큐에서 꺼낸 거리가 이미 더 짧은 값으로 갱신된 상태라면 그냥 건너뛰도록 처리했다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(E log E)
* 공간복잡도: O(N + E)

`N`은 마을의 개수, `E`는 도로의 개수이다.

### 새롭게 알게 된 점

다익스트라는 그래프에 중복 간선이 있어도 별도로 전처리하지 않아도 된다. 우선순위 큐 기반으로 항상 더 짧은 거리부터 확정해 나가기 때문에, 나중에 꺼내는 더 긴 거리는 자동으로 무시된다는 점을 이해했다.

## 문제 2

### 문제 정보

* 문제명: 네트워크
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43162
* 사용한 알고리즘 / 자료구조: 유니온 파인드(Union-Find)

### 처음 접근 방식

연결 정보 행렬을 한 줄씩 보면서 1의 개수를 세면 네트워크 개수를 구할 수 있을 거라 생각했다. 하지만 컴퓨터 A와 B가 직접 연결되어 있지 않아도 다른 컴퓨터를 거쳐 간접적으로 연결될 수 있어서, 단순히 행렬만 보는 방식으로는 정확한 네트워크 개수를 셀 수 없었다.

### 풀이 방법

1. 각 컴퓨터를 자기 자신을 부모로 갖는 상태로 `parent` 배열을 초기화한다.
2. `find` 함수는 루트 노드를 찾을 때까지 부모를 따라 올라가고, 지나온 노드들의 부모를 루트로 바로 연결해 경로를 압축한다.
3. `union` 함수는 두 노드의 루트를 찾아 다르면 한쪽 루트를 다른 쪽 루트에 연결한다.
4. 연결 정보 행렬을 순회하면서 `computers[i][j]`가 1이면 `i`와 `j`를 `union`으로 합친다.
5. 모든 노드를 순회하면서 `find(i) == i`인, 즉 자기 자신이 루트인 노드의 개수를 세어 네트워크 개수로 반환한다.

### 어려웠던 지점

경로 압축을 적용하지 않고 `find`를 구현했을 때는 답은 맞았지만, 그래프가 한 줄로 길게 연결된 경우 재귀 깊이가 커지며 비효율적이었다. 또 대각선 원소(`computers[i][i]`)가 항상 1로 주어지는 것을 처음엔 실제 연결 정보로 착각해서 혼란스러웠다.

### 해결 방법

`find` 함수 안에서 루트를 찾은 뒤 재귀적으로 돌아오면서 지나온 노드들의 부모를 전부 루트로 바로 갱신하도록 경로 압축을 추가했다. 대각선 원소는 자기 자신과의 연결이므로 네트워크 판단에는 영향을 주지 않는다는 것을 확인하고 무시해도 된다는 것을 알게 됐다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N^2 α(N))
* 공간복잡도: O(N)

`N`은 컴퓨터의 개수이며, 경로 압축을 적용하면 `find`와 `union` 연산은 거의 상수 시간에 가깝다.

### 새롭게 알게 된 점

컴퓨터 사이의 연결 여부처럼 "같은 그룹인지 아닌지"만 판단하면 되는 문제는 DFS/BFS로 그래프를 전부 탐색하지 않아도, 유니온 파인드로 그룹을 합쳐가며 훨씬 간단하게 풀 수 있다는 것을 알게 됐다.

## 문제 3

### 문제 정보

* 문제명: 순위
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/49191
* 사용한 알고리즘 / 자료구조: 플로이드-워셜, 그래프 도달 가능성

### 처음 접근 방식

주어진 승패 결과만으로 바로 순위를 정렬하면 된다고 생각했다. 하지만 모든 선수의 경기 결과가 주어지는 것이 아니라 일부만 주어지기 때문에, 직접 비교되지 않은 두 선수 사이의 승패는 다른 선수를 거쳐서 간접적으로 유추해야 했다.

### 풀이 방법

1. `N x N` 크기의 `win` 배열을 만들어 `win[i][j]`가 참이면 `i`가 `j`를 이긴다는 뜻으로 정의한다.
2. 주어진 결과 `(winner, loser)`마다 `win[winner][loser]`를 참으로 표시한다.
3. 플로이드-워셜과 같은 방식으로 세 선수 `i, k, j`를 모두 순회하면서, `i`가 `k`를 이기고 `k`가 `j`를 이기면 `i`도 `j`를 이긴다고 갱신한다.
4. 모든 선수에 대해, 자신이 이긴 선수 수와 자신에게 진 선수 수(다른 선수가 자신을 이긴 경우)의 합이 `N - 1`이면 순위가 확정된 선수로 센다.
5. 조건을 만족하는 선수의 수를 반환한다.

### 어려웠던 지점

"순위가 확정된다"는 조건이 정확히 무엇을 의미하는지 처음엔 이해하기 어려웠다. 단순히 직접 경기한 결과만 보면 되는 줄 알았는데, 간접적인 승패 관계까지 모두 포함해서 나머지 모든 선수와의 승패가 결정되어야 순위를 알 수 있다는 점을 뒤늦게 파악했다.

### 해결 방법

승패 관계를 그래프의 도달 가능성 문제로 바꿔서 생각했다. `i`에서 `j`로 가는 경로가 있으면 `i`가 `j`를 이긴다는 의미이므로, 플로이드-워셜의 삼중 반복문으로 모든 간접 승패 관계까지 전이시켰다. 이후 각 선수마다 이기거나 진 상대의 수를 세어 `N - 1`과 비교하는 방식으로 확정 여부를 판단했다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N^3)
* 공간복잡도: O(N^2)

`N`은 선수의 수이다. 모든 선수 쌍에 대해 중간 선수를 거쳐 승패를 전이시키는 과정을 거친다.

### 새롭게 알게 된 점

플로이드-워셜은 최단거리를 구할 때뿐 아니라, 이 문제처럼 "A에서 B로 도달할 수 있는가"와 같은 관계의 전이(transitive closure)를 구할 때도 활용할 수 있다는 것을 알게 됐다. 직접 연결되지 않은 관계도 중간 노드를 거쳐 모두 확인해야 하는 문제에서는 유용한 접근이었다.
