## 문제 1

### 문제 정보

* 문제명: 큰 수 만들기
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42883
* 사용한 알고리즘 / 자료구조: 그리디, 스택

### 처음 접근 방식

숫자 `k`개를 빼서 가장 큰 수를 만드는 문제라서, 처음에는 제거할 인덱스 조합을 모두 만들어 비교하려고 했다. `number`의 길이가 100만까지라 당연히 시간초과였다. 그래서 다음으로 "앞자리가 클수록 무조건 큰 수"라는 생각에, 남길 자리 수를 정해놓고 매 자리마다 가능한 구간에서 최댓값을 찾아 고르는 방식으로 바꿨다. 논리는 맞았지만 자리마다 구간을 다시 훑어서 최악의 경우 `O(N * K)`가 되어 역시 시간초과가 났다.

### 풀이 방법

1. 빈 스택을 만들고 `number`를 앞에서부터 한 글자씩 본다.
2. 스택이 비어 있지 않고, 스택의 맨 위 숫자가 지금 보는 숫자보다 작고, 아직 제거 가능 횟수 `k`가 남아 있으면 스택에서 꺼내고 `k`를 1 줄인다.
3. 이 과정을 더 이상 꺼낼 수 없을 때까지 반복한 뒤, 지금 보는 숫자를 스택에 넣는다.
4. 문자열을 다 돌고도 `k`가 남아 있으면 스택 뒤쪽에서 `k`개를 잘라낸다. 뒤쪽은 이미 내림차순이므로 뒤에서 버리는 게 이득이다.
5. 스택에 남은 숫자를 순서대로 이어 붙여 문자열로 반환한다.

### 어려웠던 지점

"제거"를 하나하나 결정하는 문제로 본 게 계속 발목을 잡았다. 어떤 자리를 뺄지 고르려고 하면 뒤에 뭐가 올지 알아야 해서 판단이 미뤄졌다. 그리고 스택으로 바꾼 뒤에도 `k`가 남는 케이스를 놓쳐서 `"4177252841", k=4`처럼 뒷부분이 내림차순인 입력에서 길이가 틀린 답이 나왔다.

### 해결 방법

보는 방향을 "뺄 숫자 고르기"에서 "앞자리를 키울 기회가 오면 즉시 버리기"로 바꿨다. 지금 보는 숫자가 앞에 쌓인 숫자보다 크면 앞의 작은 숫자는 남겨둘 이유가 없으니, 그 자리에서 바로 꺼내는 게 항상 최선이다. 이 판단이 지역적으로 끝나니 전체를 한 번만 훑으면 됐다. 남은 `k`는 "내림차순이라 꺼낼 기회가 없었다"는 뜻이므로 뒤에서 잘라냈다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N)
* 공간복잡도: O(N)

`N`은 `number`의 길이(최대 1,000,000)이다. 각 숫자는 스택에 한 번 들어가고 최대 한 번 나오므로 전체 연산은 `2N`을 넘지 않는다.

### 새롭게 알게 된 점

문자열에서 몇 개를 빼 최대/최소를 만드는 문제는 스택으로 "앞에 쌓인 값과 지금 값을 비교해 즉시 버리는" 패턴이 거의 그대로 쓰인다. 지난주 주식가격 문제에서 썼던 스택과 모양은 같은데, 그때는 "다음 큰 값을 찾는" 용도였고 이번엔 "불리한 값을 버리는" 용도였다. 같은 자료구조라도 꺼내는 조건을 어떻게 잡느냐에 따라 전혀 다른 문제를 푼다는 걸 알게 됐다.

## 문제 2

### 문제 정보

* 문제명: 섬 연결하기
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42861
* 사용한 알고리즘 / 자료구조: 그리디(크루스칼), 정렬, 유니온 파인드

### 처음 접근 방식

모든 섬이 통행 가능해야 하고 비용은 최소여야 하니, 섬마다 가장 싼 다리를 하나씩 고르면 되겠다고 생각했다. 그렇게 짰더니 같은 다리를 두 섬에서 중복으로 세거나, 이미 연결된 섬끼리 또 다리를 놓아서 비용이 과하게 나왔다. 그다음엔 비용 순으로 정렬해 앞에서부터 `n-1`개를 그냥 집었는데, 이번엔 한쪽에 다리가 몰려서 연결되지 않은 섬이 남는 케이스가 나왔다.

### 풀이 방법

1. `costs`를 비용 기준 오름차순으로 정렬한다.
2. 부모 배열 `parent`를 만들고 각 섬의 부모를 자기 자신으로 둔다.
3. `find` 함수는 부모를 따라 올라가 대표 섬을 찾고, 올라가면서 경로 압축을 해둔다.
4. 정렬된 다리를 앞에서부터 보며 양쪽 섬의 대표를 구한다.
5. 대표가 같으면 이미 연결된 섬이므로 건너뛴다. 다르면 두 집합을 합치고 비용을 더한 뒤 선택한 다리 수를 1 늘린다.
6. 선택한 다리가 `n-1`개가 되면 모든 섬이 이어졌으므로 멈추고 누적 비용을 반환한다.

### 어려웠던 지점

"싼 것부터 고르면 된다"는 직관까지는 빨리 갔는데, 그 선택이 유효한지 판단하는 기준이 없었다. 비용만 보고 집으면 사이클이 생기고, 섬마다 하나씩 집으면 중복이 생겼다. 결국 필요한 건 "이 다리가 지금까지 떨어져 있던 두 덩어리를 새로 잇는가"였는데, 그걸 확인하는 방법을 몰라서 방문 배열로 어떻게든 해보려다 더 꼬였다.

### 해결 방법

연결 여부를 집합으로 관리하면 된다는 걸 알고 유니온 파인드를 썼다. 다리를 집기 전에 양 끝 섬의 대표가 같은지 보면 사이클인지 바로 알 수 있고, 다르면 합치면서 덩어리 수가 하나 줄어든다. 섬이 `n`개일 때 덩어리를 1개로 만들려면 정확히 `n-1`번 합쳐야 하니 종료 조건도 명확해졌다. 방문 배열로는 "어느 덩어리에 속하는지"를 표현할 수 없었던 게 문제였다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(E log E)
* 공간복잡도: O(N + E)

`N`은 섬의 개수(최대 100), `E`는 다리의 개수다. 정렬이 `O(E log E)`로 가장 비싸고, 경로 압축을 한 `find`는 거의 상수 시간이라 전체는 정렬 비용에 지배된다.

### 새롭게 알게 된 점

"모든 노드를 연결하는 최소 비용"은 최단경로가 아니라 최소 스패닝 트리 문제라는 걸 구분하게 됐다. 지난주 배달·합승 택시 문제는 특정 지점까지의 거리를 줄이는 거였고, 이번엔 전체를 잇는 비용을 줄이는 거라 다익스트라 계열이 아예 맞지 않았다. 그리고 유니온 파인드는 "같은 그룹인지 확인 + 합치기"가 필요할 때 쓰는 도구이고, 몇 주 전 네트워크 문제처럼 DFS로 덩어리를 세는 것과 쓰임이 다르다는 것도 정리됐다.

## 문제 3

### 문제 정보

* 문제명: 스티커 모으기(2)
* 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12971
* 사용한 알고리즘 / 자료구조: DP, 1차원 배열

### 처음 접근 방식

인접한 스티커를 같이 뜯을 수 없다는 조건만 보고 바로 `dp[i] = max(dp[i-1], dp[i-2] + sticker[i])` 점화식을 세웠다. 일자로 늘어선 경우는 이걸로 맞게 나왔는데, 문제는 스티커가 원형으로 붙어 있다는 점이었다. 첫 번째와 마지막 스티커가 서로 인접인데 선형 DP는 그걸 모르니, 둘을 동시에 고른 답이 나와 틀렸다. 원형을 처리하려고 배열을 두 배로 이어 붙이거나 점화식에 조건을 덧붙여봤지만 경우가 계속 늘어나기만 했다.

### 풀이 방법

1. 스티커가 1개뿐이면 그 값을 그대로 반환한다.
2. 0번 스티커를 뜯는 경우를 가정하고, 마지막 스티커를 제외한 `0 ~ n-2` 구간에서 선형 DP를 돌린다. 이때 `dp[0] = sticker[0]`, `dp[1] = sticker[0]`으로 두어 0번을 반드시 포함시킨다.
3. 0번 스티커를 뜯지 않는 경우를 가정하고, `1 ~ n-1` 구간에서 선형 DP를 돌린다. 이 구간에서는 마지막 스티커를 자유롭게 고를 수 있다.
4. 두 경우 모두 `dp[i] = max(dp[i-1], dp[i-2] + sticker[i])`를 그대로 쓴다.
5. 두 결과 중 큰 값을 반환한다.

### 어려웠던 지점

원형이라는 조건을 점화식 안에서 해결하려고 한 게 가장 오래 막힌 부분이었다. "0번을 썼는지"를 DP 상태에 넣어 `dp[i][0/1]`로 만들어봤는데, 마지막 칸에서 0번 사용 여부를 보고 거르는 처리가 지저분해지고 `n`이 작을 때 인덱스가 계속 어긋났다. 그리고 0번을 포함하는 경우의 `dp[1]` 초기값을 `max(sticker[0], sticker[1])`로 잡아서, 0번을 포함한다는 가정이 깨진 채로 계산된 적도 있었다.

### 해결 방법

원형을 한 번에 풀려고 하지 말고 "0번을 뜯는다 / 뜯지 않는다"로 경우를 나누자 문제가 선형 DP 두 개로 쪼개졌다. 0번을 뜯으면 마지막은 절대 못 뜯으니 구간이 `0 ~ n-2`로 줄고, 0번을 안 뜯으면 `1 ~ n-1`이 그냥 일직선이 된다. 어느 쪽도 "첫째와 마지막을 동시에 고르는" 상황이 생기지 않아 원형 조건이 알아서 해소됐다. 0번 포함 경우의 `dp[1]`을 `sticker[0]`으로 고정한 것도 이 가정을 지키기 위한 부분이다.

### 시간복잡도 / 공간복잡도

* 시간복잡도: O(N)
* 공간복잡도: O(N)

`N`은 스티커의 개수(최대 100,000)이다. 구간을 두 번 돌지만 상수 배라 `O(N)`이다. `dp` 배열 대신 직전 두 값만 변수로 들고 가면 공간은 `O(1)`로 줄일 수 있다.

### 새롭게 알게 된 점

원형 구조의 DP는 점화식을 복잡하게 만드는 대신, 양 끝이 충돌하는 지점을 기준으로 경우를 나눠 선형 문제로 바꾸는 게 정석이라는 걸 알게 됐다. 11주차 미로 탈출에서 경유지 때문에 BFS를 두 번 나눠 돌렸던 것과 결국 같은 발상이다. 상태를 늘려 한 번에 푸는 것보다 조건을 고정해 여러 번 푸는 쪽이 코드도 짧고 실수도 적다는 게 이제 몸에 붙는 느낌이다.
