# 오답노트

## 문제 1

- **문제명:** 의상
- **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/42578
- **알고리즘 / 자료구조:** HashMap, 조합

### 접근 및 시행착오

처음에는 실제로 가능한 의상의 조합을 하나씩 만들어서 개수를 구해야 하나 생각했다. 하지만 의상의 개수는 최대 30개이고, 모든 조합을 직접 구하면 경우의 수를 계산하는 과정이 복잡해질 수 있다.

문제를 자세히 보면 같은 종류의 의상은 최대 1개만 착용할 수 있다. 따라서 각 종류별로 의상의 개수만 알고 있으면 조합의 개수를 계산할 수 있다.

예를 들어 머리 장식이 2개이고 안경이 1개라면 머리 장식은 `2개 중 하나를 선택하거나 아무것도 선택하지 않는 경우`로 총 3가지가 된다. 안경도 `1개를 선택하거나 선택하지 않는 경우`로 2가지가 된다.

따라서 각 종류별 `(의상 개수 + 1)`을 모두 곱하면 전체 경우의 수를 구할 수 있다. 단, 아무것도 입지 않는 경우는 제외해야 하므로 마지막에 1을 빼준다.

### 최종 풀이

1. `HashMap`을 사용하여 의상 종류별 개수를 저장한다.
2. 같은 종류의 의상이 나오면 기존 개수에 1을 더한다.
3. 각 의상 종류마다 `(개수 + 1)`을 전체 경우의 수에 곱한다.
4. 모든 종류를 계산한 후 아무 의상도 입지 않는 경우 1개를 제외한다.

예를 들어 다음과 같은 경우를 생각할 수 있다.

- headgear: 2개
- eyewear: 1개

각 종류별 선택 방법은 다음과 같다.

- headgear: 2개 선택 + 선택 안 함 = 3가지
- eyewear: 1개 선택 + 선택 안 함 = 2가지

따라서 전체 경우의 수는 `3 * 2 = 6`가지이고, 아무것도 입지 않는 경우를 제외하면 `6 - 1 = 5`가지가 된다.

### 복잡도

- 시간복잡도: O(N)
- 공간복잡도: O(N)

`N`은 의상의 개수이다.

### 핵심 포인트

의상의 실제 조합을 직접 만들지 않아도 각 종류별 선택 가능한 경우의 수를 곱해서 전체 조합을 구할 수 있다.

특히 어떤 종류의 의상을 선택하지 않는 경우까지 포함하기 위해 `(개수 + 1)`을 사용하는 것이 핵심이다.

### 풀이 코드

```java
import java.util.*;

class Solution {
    public int solution(String[][] clothes) {
        int answer = 1;
        
        Map<String, Integer> map = new HashMap<>();
        
        for(String[] cloth : clothes){
            String s = cloth[1];
            map.put(s, map.getOrDefault(s, 0) + 1);
        }
        
        for(String key : map.keySet()){
            answer *= map.get(key) + 1;
        }
        
        return answer - 1;
    }
}
```

## 문제 2

- **문제명:** 전화번호 목록
- **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/42577
- **알고리즘 / 자료구조:** HashMap, 문자열

### 접근 및 시행착오

처음에는 모든 전화번호를 서로 비교해서 한 번호가 다른 번호의 접두어인지 확인하는 방법을 생각했다. 하지만 전화번호의 개수가 최대 1,000,000개이기 때문에 모든 전화번호를 서로 비교하면 시간이 너무 오래 걸린다.

그래서 모든 전화번호를 `HashMap`에 저장한 뒤, 각 전화번호의 앞부분을 하나씩 확인하는 방식으로 접근했다.

예를 들어 `"1195524421"`이라는 전화번호가 있다면 앞에서부터 문자열을 잘라 다음과 같이 확인할 수 있다.

- `"1"`
- `"11"`
- `"119"`
- `"1195"`
- ...

이 중 `"119"`가 전화번호 목록에 존재한다면 `"119"`는 `"1195524421"`의 접두어이므로 바로 `false`를 반환할 수 있다.

`HashMap`을 사용하면 특정 전화번호가 존재하는지 빠르게 확인할 수 있기 때문에 모든 전화번호를 서로 비교하는 것보다 효율적이다.

### 최종 풀이

1. 모든 전화번호를 `HashMap`에 저장한다.
2. 전화번호를 하나씩 순회한다.
3. 현재 전화번호의 앞부분을 길이별로 잘라서 확인한다.
4. 잘라낸 문자열이 `HashMap`에 존재하면 다른 전화번호가 현재 번호의 접두어이므로 `false`를 반환한다.
5. 모든 전화번호를 확인했는데 접두어 관계가 없으면 `true`를 반환한다.

예를 들어 전화번호 목록이 다음과 같다고 가정한다.

```text
119
97674223
1195524421
```

`1195524421`을 확인할 때 앞부분을 순서대로 확인한다.

```text
1
11
119
```

이때 `119`가 `HashMap`에 존재하므로 `"119"`는 `"1195524421"`의 접두어이다.

따라서 `false`를 반환한다.

### 복잡도

- 시간복잡도: O(N × L²)
- 공간복잡도: O(N)

`N`은 전화번호의 개수이고 `L`은 전화번호의 최대 길이이다.

현재 코드에서는 각 전화번호마다 접두어를 확인하고, `substring()`을 사용하여 문자열을 생성한다. 전화번호의 최대 길이가 20으로 제한되어 있기 때문에 실제로는 충분히 처리할 수 있다.

### 핵심 포인트

모든 전화번호를 서로 비교하면 `O(N²)`에 가까운 시간이 필요하지만, `HashMap`을 사용하면 특정 전화번호의 존재 여부를 빠르게 확인할 수 있다.

문자열 문제에서는 전체 문자열뿐만 아니라 문자열의 앞부분이나 뒷부분을 잘라 자료구조에서 확인하는 방법도 사용할 수 있다.

### 풀이 코드

```java
import java.util.*;

class Solution {
    public boolean solution(String[] phone_book) {
        boolean answer = true;
        
        Map<String, Integer> map = new HashMap<>();
        
        for(int i = 0; i < phone_book.length; i++){
            map.put(phone_book[i], i);
        }
        
        for(int i = 0; i < phone_book.length; i++){
            for(int j = 0; j < phone_book[i].length(); j++){
                if(map.containsKey(phone_book[i].substring(0, j)))
                    return false;
            }
        }
        
        return answer;
    }
}
```

## 문제 3

- **문제명:** 예상 대진표
- **문제 링크:** https://school.programmers.co.kr/learn/courses/30/lessons/12985
- **알고리즘 / 자료구조:** 구현, 시뮬레이션

### 접근 및 시행착오

처음에는 실제 토너먼트 대진표를 배열이나 트리 형태로 만들어서 A와 B가 몇 번째 라운드에서 만나는지 계산해야 하나 생각했다.

하지만 문제의 번호 규칙을 보면 한 라운드가 끝날 때마다 참가자의 번호가 일정한 방식으로 변경된다.

예를 들어 첫 번째 라운드에서 다음과 같이 대결한다.

```text
1번 vs 2번
3번 vs 4번
5번 vs 6번
7번 vs 8번
```

각 경기의 승자는 다음 라운드에서 다음 번호를 받는다.

```text
1번 또는 2번 → 1번
3번 또는 4번 → 2번
5번 또는 6번 → 3번
7번 또는 8번 → 4번
```

즉 현재 번호를 2로 나눈 뒤 올림한 값이 다음 라운드의 번호가 된다.

따라서 실제 대진표를 만들 필요 없이 A와 B의 번호를 다음 라운드 번호로 계속 변경하면 된다.

두 번호가 같아지는 순간, 같은 대진 위치에 도달한 것이므로 해당 라운드가 두 사람이 만나는 라운드가 된다.

### 최종 풀이

1. A와 B의 번호가 같아질 때까지 반복한다.
2. 현재 번호를 다음 라운드의 번호로 변경한다.
3. 다음 라운드 번호는 현재 번호를 2로 나눈 값을 올림하면 된다.
4. 코드에서는 다음과 같이 계산했다.

```text
a / 2 + a % 2
```

예를 들면 다음과 같다.

```text
1 → 1
2 → 1
3 → 2
4 → 2
5 → 3
6 → 3
```

5. A와 B를 모두 다음 라운드 번호로 변경한다.
6. 한 번 반복할 때마다 `answer`를 증가시킨다.
7. A와 B의 번호가 같아지면 반복을 종료하고 `answer`를 반환한다.

예를 들어 `A = 4`, `B = 7`인 경우 다음과 같이 진행된다.

```text
처음
A = 4
B = 7

1라운드 후
A = 2
B = 4

2라운드 후
A = 1
B = 2

3라운드
1번과 2번이 대결
```

따라서 두 참가자는 3번째 라운드에서 만나게 된다.

### 복잡도

- 시간복잡도: O(log N)
- 공간복잡도: O(1)

매 라운드마다 전체 참가자 수가 절반으로 줄어들기 때문에 최대 반복 횟수는 `log N` 수준이다.

추가적인 배열이나 자료구조를 사용하지 않으므로 공간복잡도는 `O(1)`이다.

### 핵심 포인트

이 문제는 실제 토너먼트 구조를 만들 필요 없이 각 참가자의 번호가 다음 라운드에서 어떻게 변하는지만 확인하면 된다.

다음 라운드 번호는 다음과 같이 계산할 수 있다.

```text
(a + 1) / 2
```

현재 코드에서는 같은 의미로 다음과 같이 계산했다.

```text
a / 2 + a % 2
```

번호가 계속 줄어들다가 두 참가자의 번호가 같아지는 시점이 바로 두 사람이 만나는 라운드라는 점이 핵심이다.

### 풀이 코드

```java
class Solution
{
    public int solution(int n, int a, int b)
    {
        int answer = 0;
        
        while(true){
            
            if(a == b){
                break;
            }
            
            a = a / 2 + a % 2;
            b = b / 2 + b % 2;
            
            answer++;
        }
        
        System.out.println("Hello Java");
        
        return answer;
    }
}
```
